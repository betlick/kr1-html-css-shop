# Study Store — контрольная работа №1

Тема: **«HTML и CSS: разработка многостраничного сайта»**.

Учебный магазин техники для рабочего места: клавиатура Study Keys, наушники Focus Sound и лампа Desk Light. Пять связанных страниц, каталог, подробные характеристики, сравнение товаров и форма заявки. Товары, цены и контакты вымышлены; оплаты и отправки данных на сервер нет.

## Запуск

Скачайте проект и откройте `index.html` в браузере. Сборка, установка пакетов и подключение к базе данных не нужны. Можно использовать Live Server в VS Code или из папки проекта запустить:

```sh
python3 -m http.server 8000
```

Откройте http://localhost:8000/. Для демонстрации модального окна и обработки формы нужен включённый JavaScript. Все изображения и стили хранятся в проекте; внешних библиотек и шрифтов нет.

## Используемые технологии

HTML5, CSS3, небольшой JavaScript без библиотек, SVG, Git и GitHub Pages. CSS-фреймворки, React/Vue и backend не используются: работа посвящена HTML/CSS.

## Обязательные требования

- Пять страниц с уникальными `title` и `meta description`, общими меню и CSS.
- Семантика: `header`, `nav`, один `main` на странице, `section`, `article`, `aside`, `footer`.
- Переходы между страницами, хлебные крошки, якоря преимуществ, товаров, FAQ и подвала.
- Карточки товаров на Grid, изображения с `alt`, цены и действия.
- Таблицы с `caption`, `thead`, `tbody`, `th`, `td` и `scope`.
- Форма с именем, почтой, телефоном, товаром, датой, темой, комментарием и согласием.
- Модальное окно `<dialog>` на главной, в каталоге и на странице товаров.
- CSS-переменные в `:root`, состояния `:hover`, `:focus-visible`, `:disabled` и ошибок.
- Flexbox для меню и действий; Grid для карточек, преимуществ и каталога.
- БЭМ-именование основных компонентов.
- `relative` у карточки, `absolute` у бейджа, `sticky` у фильтра, `fixed` у кнопки «Наверх», `z-index` для слоёв.

## Доработки сверх базового примера

1. Простое оформление как в практиках: белый фон, серые шапка и подвал, синие кнопки, карточки с рамками. Локальные векторные иллюстрации товаров.
2. Сравнение трёх товаров в каталоге и полные характеристики каждого товара на одной странице с якорями.
3. Три варианта карточек: хит, новинка, скидка; старая цена у товара со скидкой.
4. FAQ на нативных `details` / `summary`: раскрывается без JavaScript.
5. Два способа заявки: быстрое окно и отдельная страница. Выбранный товар подставляется автоматически.
6. Проверка формы с подсветкой ошибок, объяснением формата телефона и сообщением о результате.
7. Доступность: skip-link, видимый фокус, `aria-current`, явные подписи полей, `aria-describedby`, `role="status"`, клавиша Escape у диалога.
8. Один медиазапрос: на ширине до 800 px карточки, преимущества и каталог становятся одной колонкой.

Одна только замена цветов и названий не является целью доработки: добавлены сравнение, подробные карточки, FAQ и связанный сценарий заявки.

## БЭМ-структура и CSS

Примеры блоков: `site-header`, `site-nav`, `hero`, `product-card`, `products-grid`, `catalog-filters`, `product-detail`, `product-table`, `order-form`, `order-dialog`, `faq`, `site-footer`.

- `product-card` — карточка как самостоятельный блок.
- `product-card__title` — её заголовок, то есть элемент.
- `product-card--discount` — вариант карточки со скидкой; используется вместе с `product-card`.
- `button button--primary` — базовый блок кнопки и его модификатор.

Оформление не привязано к `id`; идентификаторы нужны для якорей, подписей и JavaScript. Inline-стилей нет. CSS разбит комментариями на базу, навигацию, компоненты, формы и узкие экраны.

## Как работает заявка

1. В кнопке быстрого заказа записан `data-order-product="keyboard"` (или другой код).
2. JavaScript находит кнопки по этому атрибуту, сбрасывает старую форму и выбирает товар в `select`.
3. `showModal()` открывает диалог. Кнопка «Закрыть» вызывает `close()`, Escape работает нативно.
4. Ссылка `order.html?product=lamp` открывает отдельную страницу; `URLSearchParams` читает код товара. Значение принимается только если есть в списке вариантов.
5. При отправке `preventDefault()` отменяет переход. `checkValidity()` проверяет HTML-ограничения, `reportValidity()` показывает подсказку браузера, `aria-invalid` включает красную рамку.
6. При успехе форма очищается, диалог закрывается и выводится сообщение с названием товара. Настоящей отправки нет, данные не сохраняются.

Обработчики проверяют наличие элементов: подключение общего скрипта не требует модального окна на странице заявки. Атрибут `data-order-product` отделяет поведение кнопки от её CSS-классов.

## Ограничения

- Фильтр каталога — статическая разметка, разрешённая методичкой №8. Поля и кнопка отключены, пояснение видно рядом. Категории ведут к соответствующим товарам.
- Корзины, оплаты, backend и реальной отправки формы нет.
- Контакты и характеристики демонстрационные.
- Повторение шапки и формы в статических HTML-файлах осознанное: шаблонизатор и сборка не нужны. При изменении общих блоков нужно обновить все страницы.

## Как проверить

1. Открыть пять страниц через общее меню; проверить активный пункт и хлебные крошки.
2. На главной открыть якоря и FAQ; проверить «Наверх».
3. В каталоге посмотреть таблицу сравнения и перейти к любому товару через «Подробнее».
4. Для каждого товара открыть быструю заявку: выбранный товар должен совпасть с карточкой. Проверить «Закрыть», Escape и повторное открытие.
5. Со страницы товара перейти к отдельной заявке: товар должен сохраниться.
6. Отправить пустую форму, затем указать неправильные почту и телефон: должно появиться предупреждение, форма не отправляется.
7. Ввести имя `Тест`, почту `test@example.com`, телефон `+79000000000`, выбрать товар и поставить согласие. После отправки появляется сообщение об учебной демонстрации.
8. Пройти интерфейс клавишей Tab: фокус виден, поля подписаны.
9. Проверить ширины 1280 и 390 пикселей, загрузку SVG и отсутствие ошибок в консоли.
